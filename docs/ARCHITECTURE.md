# Architecture

How the IL-2 tactical radio works, for anyone (human or agent) changing it. Read this before editing; [FEASIBILITY.md](FEASIBILITY.md) holds the research and evidence behind each decision, and [ROADMAP.md](ROADMAP.md) what's left.

## The one rule

**Never claim what the integration can't establish.** Every position carries its source, its age and its coordinate frame. Replies are built only from fresh live tracks. Planned waypoints and old event snapshots are never presented as current. Destroyed or despawned aircraft never answer. Enemy aircraft are only reported once the visibility model says someone could have seen them. Tests enforce this; keep it that way.

## Data flow during a flight (`Il2Radio.exe` or `Il2Radio.Diag live`)

```
IL-2 writes ──────────────────────────────┐      LiveSession polls every ~1 s
 data\missionReport(<start>)[N].mlg chunks ──► BinaryMissionLogTail ─┐
 data\Missions\_gen.Mission (Career plan) ───► MissionPlan ──────────┤
 data\Tracks\*.acmi (Tacview, LOCKED) ──────► AcmiStream ───────────┼─► ContactTracker
 Il-2.exe memory (read-only) ───────────────► MemoryPositions ───────┤   (memory, or the ACMI as fallback; never both)
 UDP 29373 motion/telemetry ────────────────► TelemetryDecoder (display only)
                                                                      │
Numpad key (GetAsyncKeyState) ─► Keyed event: request line + mic click (immediately)
                               ─► VSS snapshot of the ACMI tail (~1.2 s, admin) ─► AcmiStream ─► ContactTracker
                               ─► RadioCommands.Execute(command, tracker, settings, SightingMemory)
                               ─► RadioResult (replies: English Text + language-neutral SpeechTokens)
                               ─► Transmitted event ─► RadioVoice (game clips → RadioEffect → PlaySound; chat only when none apply)
                                                     ─► chat sink (in-game overlay / window), synced via RadioVoice.Speaking
                                                     ─► Kneeboard.Record: a pencil mark from what the reply said
```

### Game data sources (all read-only; the game process is never written to)
- **IL-2's memory** (`Core/Memory/ObjectRoster`, `Windows/MemoryPositions`, `Windows/ProcessMemory`; since 2026-10-27, setting `positions`, default `auto`). How the layout was found and verified is in [MEMORY.md](MEMORY.md).
  - **Discovery, once per mission, in the background:** the player's log id (AType 10, `ISPL:1`) is searched for in the game's heap; the object 0x2E88 bytes before it whose first qword points into `Il-2.exe` (its class) and whose position is plausible is the player's. One scan for that class pointer then finds every object of the class (about 6 s in all). The class address differed in each of three missions, so it is learned, never fixed. A rescan every 30 s picks up spawns.
  - **Reading, every poll (~1 s) and on each radio key:** id `+0x2E88`, marker `0x84222325` at `+0x2E90`, speed `+0x2EB4`, position f64 north/height/east at `+0x2FF8`. An aircraft has one to ten objects (its parts) within its own size; `MemoryAircraft.Of` takes their median. An object whose class pointer or marker changes is dropped (freed: a wreck at ground impact, a despawn).
  - **Into the tracker:** `ContactTracker.Apply(IReadOnlyCollection<MemoryAircraft>, time)`: only ids the mission log has confirmed as aircraft; positions in `CoordinateFrame.Il2World` (the mission's own metres, so map squares need no latitude fit); `PositionSource.Memory` with the session's clock; heading = course over ground once the aircraft has moved `CourseBaselineMetres` (30 m). An aircraft memory showed before and no longer shows is `Despawned` (undone if it reappears). **Kills come only from the log:** a shot-down aircraft keeps a live memory position while it falls (~40 s, VERIFIED).
  - **One source at a time** (`LiveSession.TrackPositionsOff`): while memory is live the ACMI is still read (mission clock) but its positions are not applied and no snapshots are taken; the two frames never mix. When memory stops (IL-2 closed, a mission not generated here, nothing found), its fixes age out in 10 s and the track takes over. `positions: memory` never uses the track; `track` never reads memory.
  - **Single-player guard:** memory is read only when the log's AType 0 `MFile` contains `_gen` (Career and quick missions generate `Missions\_gen.msnbin`).
  - **Position log:** every memory read is appended to `positions-<start>.csv` beside the evidence file (`Core/Memory/PositionLog`, `LiveSession.LogPositions`): every aircraft, named or not, with the heading and status the tracker gave it. It is the flight review's ground truth when no track was recorded; its first six columns are `mem-roster --csv`'s, so `Diag mem-compare` checks it against an ACMI. Flushed each read; a write failure stops the log with a note, never the radio. About 2–5 MB an hour.

- **Mission log** (`Core/MissionLog`). IL-2's "AType" event log.
  - With `mission_text_log = 1`, IL-2 writes rotating chunks `missionReport(<start>)[N].mlg` plus `.txt` directly in `data\`, about every 33 s, and deletes the previous mission's chunks.
  - The complete `.mlg` lands in `data\FlightLogs` at mission end.
  - `BinaryMissionLog` decodes the binary format: `tick:u32 atype:u8 len:u16 payload 0x0A`, strings `len:u32 + bytes`, positions as three f32. Ticks run at 50/s.
  - It gives identities (AType 12, with a `BotPilot_*` child confirming an aircraft), the player's flight with formation numbers (AType 10), and status events: take-off, landing, damage, kill, bail-out, despawn.
  - **Positions only at events; no periodic positions in single-player.**
- **Mission plan** (`Core/MissionFile`). Career writes the sortie as text to `data\Missions\_gen.Mission`.
  - `MissionFileParser` is a generic block parser.
  - `MissionPlan` gives the player (`AILevel = 0`), each plane's `Callsign`/`Callnum`, country to coalition, and `MissionWeather` (cloud base and depth, coverage from the preset name, haze, start time).
  - Waypoints: `Routes`/`Waypoints` are the chains of direct `Targets` links per plane (used by the route gate and the corner calls); each `PlannedWaypoint` keeps Career's name (`WAYPOINT-TAKEOFF`, `CMD_Waypoint`, `CMD_AttackArea`, `WAYPOINT_LAND`; VERIFIED in the `_gen.mission` files IL-2 saved beside this install's Career tracks, 22 distinct missions, all of which the walk takes to the landing waypoint). Career does not link a sortie only waypoint to waypoint: a timer moves the flight from an attack area to its patrol loop, a counter-timer-counter from the loop to the way home, and `MCU_Deactivate`/`MCU_CheckZone` links point back or branch. So the direct chains of a real sortie are three or four pieces. `BriefedRoutes` is one sequence per flight, take-off to landing, walked through direct links first and then `MCU_Timer`/`MCU_Counter` paths (up to 6 deep), never through deactivate or check-zone links; a patrol loop is flown once round, and a direct chain ending at `WAYPOINT_LAND` is appended when the walk stops short of it. Unlinked alternate attack areas stay out. `Diag mission` prints both.
  - `Airfields` (name, country, callsign, position); `HomeField` is the player's country's field nearest the flight's `WAYPOINT_LAND` (or his start). Tusov, country 201, is at the same place in every Career mission checked.
  - Callsign words come from the install's `data\GUI\DefaultCallsigns.*` (`CallsignTable`), in English, so the text names the callsign exactly as IL-2's own chat does ("Rook"). The German recordings say other words ("Saatkrähe"); the game itself speaks one and shows the other, and so do we. A voice pack's manifest `words` only labels its clips for `voice-check`.
  - Career prefixes flight-mates' names with a 0x01 byte, here and in the log and the ACMI. Strip control characters when matching names.
- **Tacview ACMI** (`Core/Acmi/AcmiStream`). The other source of continuous positions, and the fallback when memory can't be read: every aircraft and vehicle at about 5 Hz, with absolute lat/lon.
  - Written only while a track is recording (`tacviewrecord = 1` + LCtrl+R). One mission can produce several files (`_00`, `_01`).
  - IL-2 holds the file **without read sharing**. The session reads only the new bytes through an on-demand Volume Shadow Copy (`Windows/ShadowCopy.cs`, WMI `Win32_ShadowCopy`, needs admin, about 1 s). Every snapshot is recorded in a ledger file, and leftover snapshots are cleaned up on start.
  - IL-2 quirks the parser handles:
    - unescaped commas in `Name=Type - Pilot,roster,n`;
    - the 0x01 name prefix;
    - the player named by account nickname (= `0,Author=`);
    - yaw = true heading;
    - **a closed recording removes every object in its final frame**, so removals are applied only when the next frame starts.
- **UDP telemetry** (`Core/Telemetry`). Player-only attitude and state, with **no world position**. Shown in the monitor; nothing depends on it.

### Contact model (`Core/Contacts/ContactTracker`)
- One `Contact` per aircraft, merged across sources:
  - log id, keyed `log:<id>`;
  - ACMI id, matched by pilot name, or `acmi:<id>`;
  - an aircraft the track showed before the log named it: the logged aircraft adopts that `acmi:<id>` contact (same pilot name), so the kill and the positions are one contact and its key stays the same. Before 2026-10-26 these stayed two contacts, one killed by the log and one moving on the track;
  - the player's ACMI object folded into the logged player contact.
- ACMI positions (`AcmiStream.PositionOf`): north is latitude × 111 320 m; east is longitude × 111 320 m × cos of one latitude for the whole stream, the first one seen. IL-2 writes absolute degrees (about 43° E at Stalingrad), so scaling each aircraft by its own latitude moved it east or west as it flew north: 36 km for a true 45 km on the 2026-10-26 track, which let a heading call through from beyond radio range.
- `Loss` (`LossReport`): from the log's kills and bail-outs, the aircraft credited (`AID`, null for -1: a collision or crash), whether the pilot was killed, whether he bailed out.
- `PositionFix` = position + `PositionSource` (`LogEvent` snapshot, or the live tracks `AcmiTrack` and `Memory`; `IsTrack`) + source time + heading.
- `AgeSeconds` = how far the source clock moved since the fix, plus wall time since the source last updated. A source that stops updating ages all of its fixes.
- `CoordinateFrame`: IL-2 world (log) and ACMI positions are never compared (`Navigation.Relative` returns null across frames).
- Status (`Airborne`, `Landed`, `Destroyed`, `BailedOut`, `Despawned`) comes from log events and ACMI removal. A track-caused despawn is undone if the aircraft reappears in the next segment.
- `MissionStarted` (AType 0) resets everything.

### Radio commands (`Core/Radio`)
- `RadioCommands.Execute` dispatches `RadioCommand` → `RadioResult(Outcome, Replies, Suppressed)`. `Suppressed` lists every contact deliberately left out and why; the monitor and tests use it.
- `RadioPicture.Build` (shared gate): the player must have a live track fix, memory or ACMI (else `PlayerPositionUnknown`). Candidates need a live fix younger than `MaxFixAgeSeconds` (10), must be operational, and must be within `RadioRangeMetres` (40 km).
- `FriendlyPositionsCommand` (Num1) and `FlightCommands.FlightPosition`/`Rejoin` (Num2/3) group aircraft with single-linkage (2 km, 600 m). The lowest formation number speaks.
- `FixCommand` (radio menu Kneeboard › 1; key `fixPosition`, unbound by default; built 2026-10-28): the player's own fix by a landmark, for the kneeboard. Not a transmission (`RadioCommands.IsTransmission`): no mic click and no request line; the answer is a chat line labelled "Fix" from the player, kept off the headset like the "Route" reading. Landmarks are the mission's `Airfields` only (the Stalingrad rivers, city and towns are a follow-up). A field is in sight within `AirfieldSightMetres` (12 km slant) scaled by haze and `Visibility.DaylightFactor`, with at least half the look through the cloud (`Visibility.CloudTransmission`). Within 5 km slant and 2 km above the field the answer is the ninth he is over, else the whole square, both by `MapGrid.Containing` (no margin at the lines: he sees which side he is on). An enemy with a live fix within 2 km (`PilotReport.EngagedMetres`) refuses it ("can't fix position, enemy on me"); nothing in sight is "can't place myself"; an ACMI fix is `NoCourse`. "Fix, by Tusov airfield, grid 1216-9."
- `RouteCommands` (radio menu Flight › 3–5; keys `routePosition`, `steerHome`, `steerTarget`, unbound by default; built 2026-10-28):
  - **Where am I on the route:** the player's map square (`MapGrid`, Stalingrad only, the same margins as every square), the leg of the briefed sequence he is on (`BriefedRoutes`, falling back to the chains; the nearest leg, a later leg winning a tie, and the next one once he is within 400 m of its end; "14 kilometres off the route, nearest leg three of eight" beyond 10 km), and the next waypoint as `Navigation.CourseDegrees` and whole kilometres, with its kind when Career's name says ("attack area", "landing"): "Oriole one, grid 1118-5, leg one of three. Next waypoint, heading 095, 10 kilometres."
  - **Steer home / steer to target:** course and distance to `HomeField` ("Tusov, heading 250, 19 kilometres") or to the next `CMD_AttackArea` ahead on the sequence (the nearest one once past the last; "target area, ..."). An escort, which Career briefs with only `WAYPOINT_LAND` and a cover order, says "no target area in the briefing".
  - **Frame (the honesty rule):** waypoints and airfields are mission metres (`Il2World`). Only a memory fix is in that frame (an aircraft parked at Tusov read 0.8 km from the mission file's Tusov, at the field's height, 2026-10-28), so a leg, a course or a distance is measured only from a memory fix. With an ACMI fix the outcome is `ReplyOutcome.NoCourse`: the steers say nothing, the route call names only the square (through the same Stalingrad fit every square uses), and the chat's system line is "no steer: only IL-2's memory puts you on the briefing map; the track recording is another frame". The player is listed in `Suppressed` with the reason.
  - **Who answers:** the AI leader (lowest living formation number, below the player's) when he is live within radio range and, under `pilot`, in formation with the player or able to see him this look (`PilotReport.CanSeePlayer`); under `precise`, whenever he can hear the call. Otherwise, when the player leads, flies alone, or the leader cannot place him, it is the player's own map reading: `SpeakerLabel` "Route", `Contact` the player, so the session keeps it off the headset (the leader is listed as suppressed with why). A destroyed leader is not live; the next living number leads.
  - **Tokens:** `Grid`, `Leg`, `OffRoute`, `Waypoint`, `Destination` (chat only: no recordings), then `Course` (the compass clip) and `Range` (`range.N` up to 10 km, else `range.far`).
- `EnemyCommands` (Num4/5) and `Visibility`:
  - **Observers** are the player's flight, or, flying alone, any friendly in radio range.
  - **Spotting:** each observer gets one deterministic look per 15 s slot. Detection probability scales with wingspan and drops with range, haze, darkness, an against-ground background and cloud between observer and target.
  - **Identification levels:** `Sighted`, `Class`, `Side`, `Type`, by range per metre of wingspan.
  - **Uncertainty:** hedged look-alike calls near the type limit.
  - **Memory:** `SightingMemory` (one per session) keeps a spot for 60 s after the aircraft leaves sight. Each closed ACMI frame is looked at as the track is read, so a pass between radio calls is recorded. A later call says where it was last seen, and does not follow the live position once the look is lost. Identification only improves on a look that still sees it.
  - **Vocabulary:** `AircraftTypes` maps IL-2 model names to radio words and wingspans.
  - **Direction of flight (Num4, and so the unasked picture call; built 2026-10-28, WWII-RADIO-REALISM.md finding 2):** a placed contact ends ", heading west", the eight-point compass of the group's course over ground (memory: measured over `CourseBaselineMetres`; ACMI: the yaw), with a `Heading` token after `Vertical` (the compass clip). Only from a look at `EnemyCommands.CourseLevel` (`Class`) or better: at class range the planform shows which way the nose points; a speck at `Sighted` range gets none, even when an earlier look identified it. `SightingMemory` keeps the `Course` of the last look that saw it, so a "last seen" call gives the direction it had then, never the live track's; a last look below class range leaves it out. The members' courses must agree (mean resultant length 0.7, about ±45°), so a furball has none. A group "on me" or "with me" gets none: it is fighting or flying with him. Numpad 5 keeps its own type-level heading. `PictureMark` ignores the course, so a heading change alone is not a new unasked picture (checked by replaying four 2026-10-26/27 tracks against the previous build: the same calls at the same times, only ", heading ..." added).
  - **Realism** (`RadioSettings.Realism`, `realism` in `settings.json`, default `pilot`): a speaker gives a position relative to the player only when he can see the player (the same visibility model and 15 s look) or, for the player's own flight, is in formation (within 1 km of him, `InFormationMetres`; 1.5 km before 2026-10-26; and within 300 m in height, `InFormationHeightMetres`, since a leader 716 m overhead said "you are in formation with us" on 2026-10-27; `RadioSettings.InFormation`). Otherwise he reports his own eight-point heading and altitude to the nearest 500 m, and the map square of his live position (`PlanSquare`, `MapGrid`). The player's own flight names that square only while the fix is still within 10 km of its waypoint chain. Another friendly flight names it whenever he can hear the call: Career often briefs those flights with an attack area rather than a chain, so the chain is not required of them. The square is omitted within 1 km of a 10 km line, and the ninth (the keypad cell, 1 southwest through 9 northeast) within 500 m of a line inside the square. A waypoint chain is only the gate for the player's flight, never the position anyone reports. Only the Stalingrad terrain is labeled; the latitude-to-metre fit is in FEASIBILITY.md. Any friendly inside radio range answers that way; he can hear the call. An enemy call uses the player's clock when the spotter is with him; a spotter in the fight who cannot see the player says "on me"; otherwise he uses his own clock. Counts are exact for a single aircraft, or for up to four once their shape is visible, and otherwise "a few" or "many". Ranges are close (under 2 km), a few kilometres (up to 8 km) or far. `precise` is the previous wording. The player's program and Diag default to `pilot`; `new RadioSettings()` stays `precise`, which is what the older command tests lock.
  - All tunables live in `RadioSettings` / `VisibilitySettings`; the model is a game-design approximation, documented in FEASIBILITY.md.
- **Unasked calls** (`UnaskedCalls`, `unasked` in `settings.json`, all on by default). The flight can speak without a numpad press. `unasked.route`, `unasked.contacts` and `unasked.losses` each turn one of them off; with all off, the session does not take the extra track snapshots below.
  - **Losses** (`LossCalls`) go before the other two. A flight mate down, or an enemy down, is called by a living flight mate on the frequency who came within 8 km of it in the positions remembered over the last 60 s (sampled every 2 s of track time on each look). The kill arrives with the next log chunk, up to about 30 s late, which is why it is not judged from where everyone is now. "Number one, Number six is down. Hurricane down." The mate who saw the most says them all; a mate's loss comes first; a bail-out with the pilot alive is "bailed out". He names an enemy's type inside type-identification range (180 m per metre of span), otherwise "enemy fighter". IL-2's own pilots are left to say three kinds (inferred from the log, UNVERIFIED by ear; the German pilot folders have `rep_trgdestr`, `rep_imhit`, `rep_falling` and nothing for someone else's loss): a kill credited to an AI flight mate, the player's own kill, and a flight mate shot down by an enemy whose pilot was not killed. A collision (AID -1 on both), a crash or a killed pilot is ours. Losses already in the log on the session's first look are never called. When every loss in the line is an enemy, the headset says the speaker's callsign, number and the actors' "target destroyed" (`SpeechWord.Destroyed`). A line with a flight mate's loss is chat only (`Tokens` null): no recording says a mate is down (`rep_falling` is the pilot's own "I'm going down").
  - **Cruise heading.** The lowest living formation number is the leader. About two kilometres before a corner whose next leg is a new course, that course is said once, and only while his live fix is still within 10 km of the flight's waypoint chain (`PlanSquare.MapMetres`: a memory fix as it is, on any map; an ACMI fix through the Stalingrad map fit. Before 2026-10-28 only the ACMI latitude was used, so with memory positions no corner was ever found). The course is the leg's true bearing to the nearest 5°, three figures, north as 360 (`Navigation.CourseDegrees`). The window is 400 m to 3.5 km, so a snapshot every 10 s still falls inside it at cruise. A loop of attack areas, each pointing at the next, is one closed chain, including the leg that joins it. A corner that chain leaves behind the nearest leg is still called when the nose is within 20° of it. An AI leader says a corner only once his live nose has swung 10° (or half the turn, for a small one) toward the new leg: the briefed route is not his intent. In the 2026-10-26 flight he was called "turning to heading 295" and turned north-east for the enemy instead, and the player who flew 295 lost the flight. A corner he turns away from, does not start within 60 s, or that a fight interrupts is dropped unsaid (`UnaskedCalls.TurningIn`). He says a corner, a settled course, or a break only while he is airborne and at least one other living mate, the player included, is within 4 km. A turn while he is alone, or on the ground, is followed in silence: ACMI `AGL` at or under 15 m (wheels-down reads about 1.4 m; verified on the 2026-10-27 Career track, where every aircraft sample carried `AGL`), or a landing in the mission log. The nose is still tracked, so the turn is not announced when a mate comes back into range. An AI leader's chat line for a corner he has started is "Number one, turning to heading 180." Once he is already on that course it is "Number one, heading 180." His headset line is his callsign and number, then "turning left" or "turning right" for a corner still ahead (`SpeechWord.Turn`, the shorter way round from his live nose), then the eight-point compass clip of the course. The pilot clips run `cn_01`–`cn_20` and have no zero, so they cannot say 180; the figure stays on the chat. When the player holds that formation number, the line is "Route, turning to heading 180." (on the chat, "[Route]: Turning to heading 180.") and nothing is spoken: `LiveSession` keeps the player's own lines off the headset. The token is `SpeechWord.Course`. Off the chain, or after a dropped corner, an AI leader says the course he has held within 10° for 15 s (`SettleSeconds`; three looks at the live cadence, because in the 2026-10-27 escort two looks either side of the top of a weave showed the same nose and "heading 165" was called), and only if the turn was gentler than 10°/s and the course is at least 10° from the last one called. A drift on a leg stays quiet. The player's own heading is never announced. A break, and any moment a contact is still in sight, stays off this call. Contact reports keep the eight-point compass.
  - **Break-off.** The leader's turning is counted sample by sample from the course he last held (`TurnSoFar`), so the side is the way he really turned (190 left through 095 to 360 is a left turn, not 170° right). Once it reaches 45°, not toward a briefed corner, and only while he is still leading (airborne, a mate within 4 km), he says once "Number one, engaging, turning left. Follow me." when an enemy in the picture, not a last-seen one, is within 15 km of him, else "Number one, turning left. Follow me." A leader who has reversed his turn by 10° or more between looks within the last 60 s is weaving, as an escort does over its bombers; a swing of his with no enemy to explain it is said only once it has held 8 s on that side without coming back 10° (`Meant`). In the 2026-10-27 escort every ±50° weave was a "follow me". The first swing of a weave, before any reversal, is still said. A contact only a distant mate has does not make it his fight. In the 2026-10-27 flight the new leader said it from 5 km and beyond, and again while taxiing, once with "engaging" for a Li-2 that was on his wingman 38 km away. The game's pilots spot before our visibility model does, so a turn that swings him onto a live enemy aircraft also counts (`TurnedToward`): within 15 km, on the side he turned to, at least 20° nearer his nose than off his old course, and not passed by more than 30°. That enemy is then written into `SightingMemory` as seen at side level, so a contact request agrees with what he said; the visibility model takes over after `RetainSeconds`. This is the one place an enemy enters the picture without the visibility model, and the evidence is the AI leader's own turn. In the 2026-10-26 flight the leader turned for the enemy about 70 s before the flight was shown to see it. Headset: number, `engaging` (`const\atk`), `turn.left`, `followme` (`const\ord_followme`). It goes before losses and picture calls, so a turn into a fight is not absorbed unsaid; it is said again only after he has called a cruise course. Corners are found on every look while he is still leading (`FindCorner`), so a turn onto the next leg with a contact in sight is not a break-off.
  - **Running ahead.** When the player, nose within 45° of the AI leader's, has been at least 1.5 km in front of the leader's nose (within 45° of it), clear of every mate by more than the formation distance, for 8 s while the leader held his nose within 20°, the first mate by formation number who can see the player (the spotting dice; any mate under `Precise`) says "Number one, you are a few kilometres ahead of us. Slow down and rejoin." (`rejoin` = `const\ord_rejoin`, "rejoin formation"). Again after 60 s while the gap is not closing by 300 m. It is said with a contact far off, but not while any contact is "on me". Replaying the 2026-10-26 flight: called at 2.1 km; from 4 km on, 1 km below the flight, nobody could see him.
  - **Lost sight.** When the flight saw the player within the last 2 minutes, nobody has for 20 s (longer than one 15 s spotting slot), and he is between 1.5 km and 8 km out within 60° of the leader's nose, the leader says once "Number one, we have lost sight of you. Heading south, altitude 3000 metres.": his own heading and altitude, the most he can give. Not from the ground, and not when another airborne mate is on the frequency and the leader is not with him: a two-ship has no such mate, so the leader is the flight. Said again only after the flight has seen him again. The 2026-10-27 call at 20 km, and the one from the airfield, were this gate. Under `Precise` the flight always sees him, so it is never said. Same place in the order as the ahead call. In the replay it comes at 320 s, 5 km ahead.
  - **Contact picture.** One line, the same sentence as Numpad 4, when a group is gained, lost (including "last seen"), or becomes "on me". A clock sliding from two o'clock to three o'clock is not a new picture. The line is not repeated while that picture holds. The same aircraft (the same target set, where an aircraft with a planned callsign counts as its whole flight) are not called again within 60 s of track time unless one has just come onto a pilot ("on me") or let go of him: a group drifting in and out of sight was called on nearly every 10 s look in the 2026-10-26 fight. Spotting is diced per aircraft, so each look can see a different few of one formation; on 2026-10-27 nine Ju 52s were "many" twice 22 s apart, then a "pair". Two parts of one flight in different places are therefore one picture entry. Picture calls are at least 15 s apart, except a new "on me"; a change held back keeps the old picture, so it is reconsidered on the next look. Friendly aircraft a pilot has identified beside him are "with me", which carries no `OnMe` token. Wounds stay with the game; losses are the call above.
  - **While a track is locked,** `LiveSession` reads the new ACMI bytes through the same shadow copy about every 10 s, and only if one of these calls is on. A numpad press still cuts the queue and waits out a snapshot already running. The copy costs about a second (FEASIBILITY.md); whether that hitch is acceptable in a flight is unchecked.
- **Phrasing:** `RadioPhrases` builds the English text ("Oriole one", spoken digits, clock code, metres). Each reply also carries `SpeechToken`s (`SpeechTokens.cs`), the same meaning in language-neutral form, for recorded voices. Tokens mirror the text exactly: `ContactType` carries the called type's family in `Name` only when the text names it, `ContactSide` only when the text says "enemy"/"friendly", `Hedge` when it says "possible"/"looks like".
- **Chat:** `RadioChat` turns an exchange into `ChatLine`s: the player's call (`RequestPhrase`), the replies, or a system line explaining a silence. The speaker is the callsign with its number in digits, then the name, each in brackets ("[Lumme 1] [Viktor Richter]"; "[Number 1] […]" without a callsign table; "[name]" alone outside the flight; a `SpeakerLabel` such as "[Route]"), the player's own calls included. `ChatTimeline` puts "[HH:MM:SS]" and two spaces in front, so a line reads "[16:44:52]  [Lumme 1] [Viktor Richter]: Flight of five, …". The callsign a reply opens with ("Lumme one, ") is left out of the chat text, which starts with a capital; `ChatLine.Spoken` keeps the full transmission, which the voice sync and the airtime estimate use.

### Audio
- `Core/Audio/RadioEffect`: pure DSP on 16-bit PCM:
  - squelch burst and tail with a click;
  - 300–3000 Hz Butterworth band-pass;
  - soft-clip drive;
  - in-band hiss that grows with `RangeFraction`;
  - a tanh limiter, so it never clips.
- `Core/Audio/ClipPhraser`: tokens → clip keys, most precise first, with fallbacks (`range.18` → `range.far`).
  - **Game recordings only** (decided 2026-10-26, [REQUIREMENTS-recorded-voice.md](REQUIREMENTS-recorded-voice.md)): every token is optional. A part the pack has no clip for is left out and the rest plays; the chat carries the whole sentence. Nothing returns null except a reply the pack can say none of, which is chat only. There is no Windows TTS and no phrase synthesizer: one actor per transmission.
  - **Placeholders** stand in for a whole message with no recording of its own: `NoContacts` → `ack` (the actors' `roger`); `WithUs`, `InFormation` → the close-in word for `Beside`, the speaker's angle off the player's nose (`beside.left` 30–120° left, `beside.right` the same right, `beside.behind` beyond 120°; `toLeft`/`toRight`/`toBack`), and `ack` when he is ahead; an unasked picture call for a newly gained group (in sight, not in the last picture, not called within 60 s) gets `Spotted` → `spotted` (`spt`) after the callsign, with the chat sentence unchanged; `ContactAmount` "a few"/"many" → `group`; `Destroyed` → `destroyed` (`rep_trgdestr`). A `Course` is the eight-point compass clip, after `turn.left`/`turn.right` (`trnleft`/`trnright`) when `Turn` says the leader is about to turn; the three-figure course stays on the chat. A `Heading` without a `heading` clip is the compass clip alone. Meanings from Windows speech recognition on the English actors (FEASIBILITY.md, "Placeholder clips").
  - The type name (`contact.type`) is a user-pack clip only; the class word stands in, because the game has no type-name clips. "A few kilometres" has no placeholder: a kilometre figure would claim more than an eyeball.
- `VoicePack` (JSON manifest; clips read in place via `{il2}`), `ClipAudio` (WAV/Ogg decode via NVorbis, resample, loudness match, crossfade, silence trim), `ClipVoice` (render).
- `Windows/VoiceSelection` picks a pack per speaker nation (`voice` setting, `--voice auto|off|<pack>`). User packs win over the game's; the repository's `voices/*.json` manifests are embedded in `Il2Radio.Windows`, and a same-named manifest in a `voices` folder overrides the built-in one. A speaker no pack covers is chat only. `voice: "tts"` is reported as a bad setting.
- `Windows/RadioVoice` runs a single background queue:
  - each item is rendered from clips, put through the effect, and played with winmm `PlaySound`. An item no clip can say still takes its turn: `Speaking` fires with a zero duration and nothing plays, so its chat line appears where the voice would have started it;
  - a new request drops queued items;
  - `PlayKeyClick` interrupts for immediate feedback;
  - the `Speaking` event reports when each transmission really starts.
- `Windows/Il2AudioMeter` watches Il-2.exe's audio-session peak meter, so replies wait while IL-2's own radio is talking. It's a heuristic and unverified.

### On-screen chat
- `Core/Radio/ChatTimeline`, shared by every output:
  - when lines appear (synced to `Speaking`, with a timeout);
  - a 14 s hold, then a fade;
  - 8 lines on screen;
  - every line, live or paged, starts with "[HH:MM:SS]" and two spaces in front of the speaker (or of the text when there is none);
  - 200-line history paged with Num7 (older) / Num9 (newer). Paging counts pages back from the newest, not lines: the oldest page is clamped to the log's first lines, so Num9 from it lands on the next page, and only Num9 on the newest page returns to the live lines. Each line is stamped with the mission clock (`MissionClock`), the time a cockpit watch shows: ACMI `ReferenceTime` plus `#t` once a frame has been read, and until then the log's `GTime` plus the newest tick. While a track is recording, its file size is polled (visible even though IL-2 locks the file); 3 s without growth pauses the clock with the sim. When recording stops, that pause ends and a newer log tick may move the clock forward, never backward. A new mission freezes the stamps already shown. Before any sample, the stamp is the wall clock;
  - the Num0 menu (`ShowMenu`/`CloseMenu`), shown in the live lines' place by the window outputs.
- `Core/Radio/RadioMenu` + `Windows/RadioMenuInput`: the radio menu, a tree of entries (`RadioMenu.Default`: Flight › (flight position, rejoin, where am I on the route, steer home, steer to target), friendly positions, Enemy ›, Radio log ›, Kneeboard › (fix position, small, large, put away); each level fits Num1–Num5). The menu key opens it, steps back a level, and closes it at the top; the quit key closes it; it closes after the 14 s hold. While it is open, `KeyBindings.PressedDigits` (Num1–Num9, polled every tick) choose entries, and radio keys bound to numpad digits don't fire their own calls; the open state is taken before the tick's keys, so the digit that closes the menu can't also fire. A chosen command goes through `RequestAsync` like its key. Keys are still only observed, never consumed. Outputs get `IChatSink.ShowMenu(view or null)`; `InGameChat` draws it with `RadioMenuPanel` as a second layer whose bottom sits just above the log's area.
- `Windows/InGameChat` (`ingame`, the default): **the fullscreen path.** RivaTuner Statistics Server was the fullscreen output until 2026-10-28; it was removed (with its sink, shared-memory slot, presets, `--rtss-*` flags and start-up check) once `ingame` had held up in a flight. Old `chat.rtss*` settings are read and dropped; `chat.output: "rtss"` is reported. The window outputs stay for a windowed IL-2 or a second screen.
  - Loads OverlayKit's host DLL into `Il-2.exe` once it runs (`OverlayInjector`, retried every 3 s for a new IL-2 process), waits for it to report frames, then renders the lines with `ChatOverlay.DrawLines` (the window overlay's exact look) onto a premultiplied bitmap at the game's back-buffer size and publishes it as one `OverlayLayer` named "IL-2 Tactical Radio".
  - Placement uses the overlay's screen fractions (`chat.windowArea`, kept clear of IL-2's text) and its 1080-line font size, scaled to the back buffer. It redraws only when the visible text or fade changes (50 ms tick).
  - The kneeboard is a third layer (`ShowKneeboard`, z-order 2), drawn by `KneeboardPanel` and redrawn only when `KneeboardPicture.Signature` changes (ages in whole minutes, fade to two places, the dead-reckoning patch to the metre), at most once per 50 ms tick. Its place is `ChatOptions.KneeboardAt` (`Core/Osd/KneeboardPlacement`).
  - Disposing the sink removes the layers at once. The DLL stays in IL-2 until the game exits and draws nothing without layers.
- `Windows/ChatOverlay`: a click-through, layered, topmost window styled like IL-2's message line (`Il2ChatStyle`). **IL-2 in exclusive fullscreen hides it whenever the game has focus (verified)**, so it's for windowed mode or a second screen.
- `Core/Osd/Il2ScreenAreas`: estimated areas of IL-2's own message line and subtitles, which the outputs keep clear of.

### Kneeboard (`Core/Radio/Kneeboard`, `KneeboardSheet`; `Windows/KneeboardPanel`; built 2026-10-28)
The player's own sketch of the briefed area, so he need not open IL-2's map. Drawn only by `ingame`. Mockup: [mockups/kneeboard-plot.svg](mockups/kneeboard-plot.svg).
- **Nothing on it is live.** `LiveSession.Plot` hands every reply (asked for, in `Describe`, or unasked, in `DeliverUnasked`) to `Kneeboard.Record` at the moment it is said, with the player's own compass (`LastFix.Heading`) and the cockpit watch. A mark is worked out from the reply's `SpeechToken`s, which mirror the words exactly: a `Grid` token is the square or ninth said (`MapGrid.Bounds`), a `Clock` is laid off the player's mark on his compass (±15°), a `Bearing` or `Steer` ±22.5° (pilot) or ±5° (precise), and the range is the band said (close 0–2 km, a few kilometres 2–8 km, far 8–16 km) or the figure ±10 %. `RadioReply.FromSpeaker` marks a place measured from the speaker ("at my two o'clock", "on me"), which the tokens alone cannot tell from "your": it is laid off the speaker's own last mark, as a ring round him when only his clock was said (his nose is not known). A mark never moves once made; a newer reply about the same aircraft (contacts: any shared member) replaces it. Every patch carries the uncertainty of what it was laid off. Nothing reads the tracker's positions. Replies are plotted only while the player's fix is from memory (`Il2World`): a square said from an ACMI fix went through the latitude fit, so with `positions: track` the sheet stays bare.
- **The player's mark** comes only from an ally or his own look: the AI leader's route reply (not his own "Route" reading, which is reading the game), a mate who has him "in formation" or "with us" while that mate's own mark is fresh (`AnchorFor`, 3 min), a mate who placed himself off the player while his own mark was known (the reverse bearing), or `FixCommand`. Each fix starts **dead reckoning** (`Advance`, on every memory read): the mark moves by his course over ground and speed from memory, his instruments, with a steady error drawn per fix (up to ±6° and ±8 %, seeded by the fix's time), and its radius grows by `DriftPerMetre` (0.10) of the distance flown plus `DriftPerMinute` (300 m), so its middle is not the truth and it is soon no free GPS; past `LostBeyondMetres` (25 km) it is dropped. SPECULATIVE; to be tuned in a flight.
- **Mates** are marked where they last reported (a square, or a place off the player); one in formation is a note beside the player's mark ("1, 3 with you"). **Contacts** are marked where they were called, with their direction of flight when the call gave one. Marks are full for a minute, then fade to 0.25 at eight; contacts go after 10 minutes, mates after 15, the fix after 30.
- **The sheet** (`KneeboardSheet.For`): the player's flight's briefed route (`BriefedRoutes`, keyed by the flight's leader, so the whole flight is searched) and its home field, plus one 10 km square of margin, at least five squares each way (an escort is briefed with only its landing point), widened to a width-to-height ratio of 1 to 1.5 and snapped out to the grid lines. It never pans; a player's mark off it is named by its edge ("off the sheet, north-east"), mates and contacts off it are not drawn. Square numbers only on Stalingrad (`MapGrid`). `Reset` on a new `_gen.Mission` and on each AType 0.
- **Look** (`KneeboardPanel`): a period kneeboard rather than a table. Folded map paper (grain, darker edges, one crease) clipped to a dark board; a fine printed grid in a double neat line, square numbers only in the margins (column along the top, row down the side); the briefed route, each leg's course and distance (written once per leg, on the left of the way it is flown, so out and back legs do not collide), the target ringed and hatched and the home field in graphite pencil; the radio's marks in blue and red pencil (a hatched fix cell, a dashed DR ring, a crossed contact with an arrow); typewriter type for printed parts and handwriting for notes. Every wobble and the grain are seeded by what they draw, never by the clock, so the once-a-second redraw does not shimmer.
- **Views** (`KneeboardView`): hidden, small (the sheet, marks and scale bar; 30 % of the screen height) and large (title, square numbers, a typed key, a footer with the last fix and the last two route or steer replies; 56 %). The `kneeboard` key (`Num/`, free in IL-2's default binds: `Num*` resets the zoom, `Num+`/`Num-` zoom) cycles them; the radio menu's Kneeboard › sets one. `LiveOptions.KneeboardChanged` lets the app write the view back to `settings.json` (`MainForm.RememberKneeboardView` changes only `kneeboard.view` in the file, so unapplied edits on the Settings tab stay unsaved).
- **Placement** (`KneeboardPlacement`): a preset pins that corner or side-middle 2 % of the screen height in, so the large view grows away from it; `custom` is the top-left pixel, scaled from `kneeboard.customScreen` (filled from `startup.cfg` when the Settings tab saves it). Always clamped on screen.
- `Diag kneeboard-test [mission]` puts a Career mission's flight on its second leg in memory positions, asks the real commands, flies four minutes of dead reckoning, and writes both views as PNGs.

## The app (`Il2Radio.App`)
- **Window:** WinForms (`OutputType` WinExe). Status shows the compact flight view. Help (`Core/Radio/RadioGuide`) explains what the radio is for and when to use each call, for any air force, with the keys currently set on the form. Settings edits every value in `settings.json`. Diag stays a console. The window is not topmost, so it does not cover IL-2.
- **Look:** `Brand` holds the palette, fonts and art, all drawn in code: a generic top-view fighter with no national markings, the round emblem, and the header (a finger-four with contrails at dusk). `BrandControls` has the painted `HeaderBanner`, the `NavStrip` that draws the tabs and the radio-state pill, `PageHost` (a TabControl with its own headers removed, so code still selects pages through it) and `SectionRule` headings. `tools/BrandArt` renders `app.ico` (exe, window and installer icon) and `docs/images/` from the same code; run `dotnet run --project tools/BrandArt` after changing `Brand.cs`. Nothing comes from IL-2's files.
- **Start-up:** a single-instance mutex (a second copy shows a message and exits); `settings.json` beside the exe (`Core/Settings/AppSettings`: every value defaulted, unknown names rejected, each bad value reported by its setting name; created with all defaults on first start). A bad file or a missing IL-2 folder leaves Settings open instead of exiting. Everything is resolved from `AppContext.BaseDirectory`, because an elevated start from Explorer runs in System32.
- **Checks** (`StartupChecks`), each an `[ok]`/`[!!]` line kept on the Status tab:
  - administrator rights (the `app.manifest` asks for `requireAdministrator`);
  - the required `startup.cfg` outputs (`Core/Il2Outputs`: `mission_text_log`, `tacviewrecord`; telemetry is Diag-only). If IL-2 is closed it asks in a dialog, with a backup, only on Yes (Enter does not mean yes);
  - the overlay window with IL-2 in exclusive fullscreen (hidden there; `ingame` is suggested).
  - Failed checks also go to the chat output through `LiveSession.AlertEachMission`: at start-up and again at each mission start.
- **Track-recording reminder:** `LiveSession` takes the running mission's start time from the log-chunk names (`missionReport(<local start>)[N]`). A mission counts as running while its chunks grew in the last 90 s. Recording means the newest ACMI created since the mission started fails a shared open, because IL-2 locks it exactly while writing it. `Core/TrackRecordingWatch` decides when to remind: once per stretch without recording, `recordingReminderSeconds` in. A mission first seen after that grace was already over, as when the program is restarted mid-mission, gets a grace of its own from then: on 2026-10-27 a restart 21 minutes in reminded on its first poll, before it had looked for the track IL-2 was still writing. The reminder goes to the Status tab and the chat output.
- **Compact view** (`LiveOptions.Compact`, delivered to the window through `LiveOptions.Status` so the console is not redrawn): mission, track and player state, start-up results, and the radio's own replies. It shows no contact table and no "silent: ... because" lines, which would name aircraft nobody reported. No UDP telemetry is opened (`LiveOptions.UdpPort = null`), so SRS or shaker tools keep the port.
- **Applying settings:** the volume replaces `RadioVoice`'s effect settings and is used on the next transmission. Everything else is written to `settings.json` and applied by stopping the session and starting it again in the same process. Save and apply is that restart.
- **Keys** (`Windows/KeyBindings`, names in `Core/Input/VirtualKeys`): bindings from the settings; the menu, legend and log hint are built from them. The Settings tab captures a key into the box.
- **Exit:** the quit key, Quit, or closing the window cancels the session and waits up to 4 s, so the in-game layers are removed and `logs\evidence-*.md` is written. The session runs off the UI thread; status is marshalled back onto it.
- **Publish:** `dotnet publish src/Il2Radio.App` → `publish\Il2Radio.exe` (win-x64, self-contained, single file, compressed; publish-only properties under `_IsPublishing`).

## Working on this repo
- **Build and test:** `dotnet test` at the root. If the user's `live` session or `Il2Radio.exe` is running it locks its `bin\Debug`; then run `dotnet test tests/Il2Radio.Core.Tests` and build the programs elsewhere with `dotnet build src/Il2Radio.Diag -o <scratch dir>` (or `src/Il2Radio.App`).
- **Admin:** live positions need an elevated terminal (VSS). Non-elevated runs work, but report the ACMI as locked.
- **Testing:** tests build scenarios from synthetic ACMI text (`TestSupport.Acmi.Object`) and log events (`MlgWriter`, or event records directly), with `ManualTimeProvider` for ages. Visibility tests use near-certain spotting settings, so identification ranges are deterministic. Avoid rounding boundaries in expected text: 45° bearings, x.5 km ranges.
- **Verified vs assumed:** say which in docs and comments ("VERIFIED", "UNVERIFIED", "inferred from file names"). A lot here is reverse-engineered from the user's own files.
- **Don't:**
  - touch the IL-2 process or its memory, or inject anything;
  - modify game files (only `startup.cfg`, with a backup, and only with the user's consent);
  - copy or commit IL-2's audio;
  - run `chat-test`, or a second `live` or `Il2Radio.exe`, while one of them is running (they share the in-game layers "IL-2 Tactical Radio" and the numpad);
  - download models without asking.
- **Real data for replays** lives in the user's install: `data\Tracks\*.acmi`, `data\FlightLogs\*.mlg`, and the current mission's `data\missionReport(...)[N].*` chunks. IL-2 deletes the previous mission's chunks, so an older ACMI replays without flight membership.
